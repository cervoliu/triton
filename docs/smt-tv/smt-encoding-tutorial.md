# How the Triton SMT Equivalence Checker Works — A Worked Example

This document walks one real kernel pair through the entire
translation-validation pipeline: an `add` kernel generated by **ninetoothed**
and the matching `add` kernel generated by **torch-inductor**
(`torch.compile`), taken from the `ntops_vs_torch_triton` artifact set. Every
IR fragment, SMT formula, solver verdict, and counterexample below is the
actual output of the tools; the appendix gives the commands to reproduce each
one.

**The claim being checked.** Both kernels are supposed to compute
`out = a + 0.75·b` elementwise over two contiguous 4×8 float32 tensors. The
checker either *proves* that no input makes their outputs differ, or returns a
concrete input on which they disagree, or refuses to answer (`UNSUPPORTED`) —
it never guesses.

---

## 1. Pipeline overview

```
kernel A (.py or .ttir)  ─┐
                          ├─►  merged module (@src/@tgt)
kernel B (.py or .ttir)  ─┘         │
                                    ▼
                     triton-opt --convert-triton-to-smt      (Part B: the encoder)
                                    │   two smt.solver scopes
                                    ▼
                     mlir-translate --export-smtlib          (Part A: Real-sort patch)
                                    │   SMT-LIB 2 text
                                    ▼
                                   Z3
                                    │
                     scope 0: unsat ⇒ addressing is identity (else UNSUPPORTED)
                     scope 1: unsat ⇒ EQUIVALENT, sat ⇒ counterexample model
```

The driver (`python/triton/tools/smt_equivalence.py`) automates the chain and
maps the two `check-sat` answers to a verdict:

| scope 0 (addressing) | scope 1 (difference) | verdict |
|---|---|---|
| unsat | unsat | **EQUIVALENT** |
| unsat | sat | **NOT_EQUIVALENT** (+ model) |
| sat | — | **UNSUPPORTED** (non-identity addressing) |
| unknown/timeout | — | **UNKNOWN** |

Everything runs host-side on TTIR — no GPU, no `ptxas`.

## 2. The two kernels

### 2.1 torch-inductor side

Inductor emits a flat 1-D "pointwise" kernel; the tensor is treated as 32
contiguous elements and `alpha = 0.75` is baked in as a constant:

```python
def triton_poi_fused_add_0(in_ptr0, in_ptr1, out_ptr0, xnumel, XBLOCK: tl.constexpr):
    xnumel = 32
    xoffset = tl.program_id(0) * XBLOCK
    xindex = xoffset + tl.arange(0, XBLOCK)[:]
    xmask = xindex < xnumel
    x0 = xindex
    tmp0 = tl.load(in_ptr0 + (x0), xmask)
    tmp1 = tl.load(in_ptr1 + (x0), xmask)
    tmp2 = 0.75
    tmp3 = tmp1 * tmp2
    tmp4 = tmp0 + tmp3
    tl.store(out_ptr0 + (x0), tmp4, xmask)
```

Its TTIR (`XBLOCK = 32`), after `--strip-debuginfo`:

```mlir
tt.func public @tgt(%arg0: !tt.ptr<f32>, %arg1: !tt.ptr<f32>, %arg2: !tt.ptr<f32>) {
  %cst    = arith.constant dense<7.500000e-01> : tensor<32xf32>
  %cst_0  = arith.constant dense<32> : tensor<32xi32>
  %c32    = arith.constant 32 : i32
  %0  = tt.get_program_id x : i32
  %1  = arith.muli %0, %c32 : i32
  %2  = tt.make_range {end = 32 : i32, start = 0 : i32} : tensor<32xi32>
  %3  = tt.splat %1 : i32 -> tensor<32xi32>
  %4  = arith.addi %3, %2 : tensor<32xi32>              // xindex = pid*32 + lane
  %5  = arith.cmpi slt, %4, %cst_0 : tensor<32xi32>     // xmask  = xindex < 32
  %6  = tt.splat %arg0 : !tt.ptr<f32> -> tensor<32x!tt.ptr<f32>>
  %7  = tt.addptr %6, %4
  %8  = tt.load %7, %5                                  // a
  %9  = tt.splat %arg1 ...
  %10 = tt.addptr %9, %4
  %11 = tt.load %10, %5                                 // b
  %12 = arith.mulf %11, %cst : tensor<32xf32>           // b * 0.75
  %13 = arith.addf %8, %12 : tensor<32xf32>             // a + b*0.75
  %14 = tt.splat %arg2 ...
  %15 = tt.addptr %14, %4
  tt.store %15, %13, %5                                 // out[xindex] = ...
  tt.return
}
```

#### 2.1.1 逐 operation 的 SMT 编码（对照 `formalize-demo` 的写法）

下面按 `formalize-demo/semantics/README.md` 的方式，把这个 kernel 当成一段
SSA 程序逐条翻译。翻译函数的形状是：

```text
[[op]] : SSAEnv -> SSAEnv        （对一个固定的符号输出 index i 求值）
```

**共同前提。** 与 formalize-demo 不同的两点：整数域用**定宽 bit-vector**
而不是无界 `Int`（wrapping、signed/unsigned 语义是精确的）；tensor 值不再用
lane-indexed 函数 `f(pid, lane)` 表示，而是 encoder 预先对被观察的输出
index `i : (_ BitVec 32)` 做 **writer decomposition**：

```text
pid  = i udiv 32        （BLOCK = 32，从本函数的 tt.make_range 读出）
lane = i urem 32
A, B, Out0 = arg0, arg1, arg2 : (Array (_ BitVec 32) Real)
```

即每个 tensor 值只编码"负责写 `out[i]` 的那一个 lane 上的取值"。直线型、
恰好一个 store、identity addressing 的 contract 保证 lane 之间互不作用，
所以对全称量化的 `i` 证明性质就等于对所有元素证明（scope 0 专门负责验证
这个 decomposition 是合法的，见 §4）。浮点值取**理想实数语义**：`mulf`、
`addf` 是精确实数运算，不建模舍入/NaN/Inf。

以下每条 TTIR operation 后面给出编码规则和它在 `/tmp/cross/add.smt2`
scope 1 里对应的实际 SMT 项（`tmp_*` 名字均为导出文件原文）。

```mlir
%cst   = arith.constant dense<7.500000e-01> : tensor<32xf32>
```
splat 常量编码成单个 `Real` 常量，且是**精确二进有理数**：`0.75 ↦ (/ 3.0 4.0)`，
没有二进制↔十进制漂移；非有限常量（±inf/NaN）会被拒绝。

```mlir
%cst_0 = arith.constant dense<32> : tensor<32xi32>
%c32   = arith.constant 32 : i32
```
整数常量编码成 32 位 bit-vector 字面量 `#x00000020`；splat tensor 与
scalar 编码相同（每个 lane 取值一样，而我们只跟踪一个 lane）。

```mlir
%0 = tt.get_program_id x : i32
```
不枚举 launch grid，直接编码成 writer decomposition 里的
`pid`：`tmp_1 = (bvudiv i #x00000020)`。仅支持 axis x；y/z 会被拒绝。

```mlir
%1 = arith.muli %0, %c32 : i32
```
逐 lane 的整数乘法，bit-vector 语义（溢出 wrap）：
`tmp_2 = (bvmul tmp_1 #x00000020)`，即 `xoffset = pid * 32`。

```mlir
%2 = tt.make_range {end = 32 : i32, start = 0 : i32} : tensor<32xi32>
```
`tl.arange(0, 32)` 在被观察 lane 上的值就是 `lane` 本身：
`tmp_0 = (bvurem i #x00000020)`。同时它把本函数的 `BLOCK` 定为 32
（`end − start`），供 decomposition 使用。

```mlir
%3 = tt.splat %1 : i32 -> tensor<32xi32>
```
`tt.splat` 是恒等映射：scalar 的编码本来就是"每个 lane 相同的值"，
不产生任何 SMT 项。

```mlir
%4 = arith.addi %3, %2 : tensor<32xi32>              // xindex
```
`tmp_3 = (bvadd tmp_2 tmp_0)`，即 `xindex = pid*32 + lane`。代入
decomposition 后 `xindex = (i udiv 32)*32 + (i urem 32)`，由除法恒等式
**恒等于 `i`** —— 这正是 scope 0 要求解器证明的事实。

```mlir
%5 = arith.cmpi slt, %4, %cst_0 : tensor<32xi32>     // xmask
```
`cmpi` 按谓词精确编码；`slt` 是**有符号**比较：
`tmp_10 = (bvslt tmp_3 #x00000020)`。`slt ≠ ult` 在这里不是学究气——
§6.1(b) 的跨框架反例恰好出在 `i` 最高位为 1 时这个 signed 比较仍为真。

```mlir
%6 = tt.splat %arg0 : !tt.ptr<f32> -> tensor<32x!tt.ptr<f32>>
%7 = tt.addptr %6, %4
```
指针编码成二元组 `(memory array, bv32 offset)`。参数指针是
`(arg0, #x00000000)`；`tt.addptr` 只移动 offset：
`tmp_7 = (bvadd #x00000000 tmp_3)`。地址以**元素**为单位，不是字节。

```mlir
%8 = tt.load %7, %5                                  // a
```
带 mask、无 `other` 的 load 编码成裸的数组读取：
`tmp_8 = (select arg0 tmp_7)`。mask 为 false 时读到的值是任意的，但
不影响最终状态——对应的 `tt.store` 被同一个 mask 屏蔽（与
formalize-demo 的前提一致）。若源码写了 `other=0.0`，则编码成
`ite(mask, select(...), 0.0)`。

```mlir
%9  = tt.splat %arg1 ...
%10 = tt.addptr %9, %4
%11 = tt.load %10, %5                                // b
```
同上，作用于 `arg1`：offset `tmp_4 = (bvadd #x00000000 tmp_3)`，
`tmp_5 = (select arg1 tmp_4)`。（encoder 不做 CSE，`tmp_4`/`tmp_7`
是两个相同的项，由求解器自行合并。）

```mlir
%12 = arith.mulf %11, %cst : tensor<32xf32>          // b * 0.75
```
理想实数乘法：`tmp_6 = (* tmp_5 (/ 3.0 4.0))`。

```mlir
%13 = arith.addf %8, %12 : tensor<32xf32>            // a + b*0.75
```
理想实数加法：`tmp_9 = (+ tmp_8 tmp_6)`。到这里，被观察 lane 上的
store value 已经是封闭形式 `A(i) + B(i)·(3/4)`。

```mlir
%14 = tt.splat %arg2 ...
%15 = tt.addptr %14, %4
tt.store %15, %13, %5
```
store 不立即改写内存，而是记录为本函数**唯一的 store effect**
`(array = arg2, offset = tmp_3, value = tmp_9, mask = tmp_10)`，之后
两个 scope 各用一次：

- **scope 0**（addressing identity）：断言 `(distinct offset i)`，
  Z3 回答 `unsat` ⇒ store 地址恒等于 `i`，writer decomposition 合法；
- **scope 1**（equivalence）：构造最终状态
  `tmp_11 = (ite tmp_10 tmp_9 (select arg2 i))`，其中
  `(select arg2 i)` 是输出数组的初始内容 `Out0(i)`（mask 为 false
  的元素保持原值）。

```mlir
tt.return
```
函数结束。contract 检查：恰好一个 store，否则 pass 报错拒绝。

**最终输出数组**（与 formalize-demo 的 `NaiveOut(i)` 形式对齐）：

```text
TorchOut(i) = ite( bvslt(i, 32),  A(i) + B(i)·(3/4),  Out0(i) )
```

其中 `xindex = i` 已由 scope 0 证明，所以 mask 和地址都直接以 `i`
表达。等价性检查（scope 1）断言的正是
`(distinct TorchOut(i) NinetoothedOut(i))`，`unsat` ⇒ 两个编译器在
每个输出元素上计算同一个函数。

### 2.2 ninetoothed side

Ninetoothed generates a *stride-general* kernel: each tensor arrives as a
`(pointer, size₀, size₁, stride₀)` group (`stride₁ = 1` is specialized away by
Triton), `alpha` is a runtime scalar, and the tile size is `BLOCK = 512`. Its
addressing recomputes 2-D coordinates from the linear index:

```mlir
%16 = arith.addi (tt.splat pid*512), make_range(0,512)   // idx  = pid*512 + lane
%23 = arith.divsi %16, size1                             // row  = idx / 8
%29 = arith.remsi %16, size1                             // col  = idx % 8
%36 = arith.addi (arith.muli %23, stride0), %29          // off  = row*stride0 + col
tt.store (tt.addptr out, %36), value, mask
```

and its store mask is a **ten-conjunct chain of `arith.andi` over `i1`**
(bounds on `pid`, `lane`, `idx`, `row`, `col` — ninetoothed emits both `< n`
and `>= 0` guards for each).

For the cross-framework demo the shape/stride/alpha arguments are specialized
to the recorded instance (`size₀=4, size₁=8, stride₀=8, alpha=0.75`) by a
script under `/tmp` (`smt_cross_demo.py`); the checker itself is unchanged.
After specialization both signatures are `(!tt.ptr<f32>, !tt.ptr<f32>,
!tt.ptr<f32>)` — the contract requires identical signatures because the two
functions must range over the *same* symbolic inputs.

## 3. The value encoding

The encoder (`lib/Conversion/TritonToSMT/TritonToSMTPass.cpp`) maps every SSA
value of the kernel to an SMT term:

| Triton/MLIR object | SMT sort | semantics |
|---|---|---|
| `f32`/`f16`/… value | `Real` | **ideal real arithmetic** — no rounding, NaN, ±inf, signed zero |
| `iN` value (N > 1) | `(_ BitVec N)` | faithful machine integers: wrapping, signed/unsigned distinction |
| `i1` value | `Bool` | predicates/masks are booleans |
| `!tt.ptr<T>` argument | `(Array (_ BitVec 32) sort(T))` + a bit-vector offset | memory is an array from 32-bit element indices to values |
| tensor of any of these | *the same sort as its scalar element* | see §4 |

Two deliberate choices define the tool's character:

- **Floats are ideal reals.** This makes algebraic rewrites (`x−y ≡ x+(−y)`,
  FMA fusion, factoring) provable — the point of the tool — at the price that
  IEEE-754 effects are invisible. A rewrite that is unsafe *only* under
  rounding is reported equivalent. This is an explicit, documented modeling
  assumption, not an oversight (roadmap: an FP-error domain reusing the same
  per-op dispatch).
- **Integers are faithful bit-vectors** at their true width. `i8` overflow
  wraps; `slt` and `ult` are different predicates. The checker correctly
  distinguishes `(x+1) > x` from `true` for `i8` x = 127.

Float constants are emitted as **exact dyadic rationals**: `0.75` becomes
`(/ 3.0 4.0)` — no binary-to-decimal drift. Non-finite constants (`inf` as a
reduction seed, for instance) are rejected loudly.

## 4. Where the tensors go: one symbolic output index

The key idea that makes elementwise kernels decidable: the encoder never
materializes tensors. It picks **one symbolic output index** `i` (a 32-bit
bit-vector constant) and encodes *the lane of each function that writes
`out[i]`*, using the writer decomposition

```
pid  = i udiv BLOCK          lane = i urem BLOCK
```

with each function's own `BLOCK` (detected from its `tt.make_range`; 32 for
the Inductor kernel, 512 for ninetoothed). Then:

- `tt.get_program_id x` encodes to `pid`;
- `tt.make_range {0..BLOCK}` encodes to `lane`;
- `tt.splat` is the identity — a scalar *is* its per-lane value;
- every tensor op becomes the corresponding scalar SMT op on that lane.

This is sound for the accepted contract (straight-line, one store, identity
addressing) because lanes never interact: proving the property for a
*universally quantified* `i` proves it for every element at once. Ops that mix
lanes — `tt.reduce`, `tt.dot`, `tt.trans` — are exactly the ones the contract
rejects.

**Scope 0 exists to validate this decomposition.** It asserts that the store
offset does **not** equal `i`, for either function; `unsat` proves the store
address is identically `i`, i.e. the function really writes `out[i]` from
`(pid, lane)`. This is the actual scope 0 of the demo pair:

```smt2
(set-logic ALL)
(declare-const i (_ BitVec 32))
(declare-const arg0 (Array (_ BitVec 32) Real))   ; a
(declare-const arg1 (Array (_ BitVec 32) Real))   ; b
(declare-const arg2 (Array (_ BitVec 32) Real))   ; out
(assert (let ((tmp   (bvurem i #x00000020)))          ; torch: lane = i % 32
        (let ((tmp_0 (bvudiv i #x00000020)))          ;        pid  = i / 32
        (let ((tmp_1 (bvmul tmp_0 #x00000020)))
        (let ((tmp_2 (bvadd tmp_1 tmp)))              ;        xindex = pid*32+lane
        (let ((tmp_3 (bvadd #x00000000 tmp_2)))       ;        store offset
        (let ((tmp_4 (distinct tmp_3 i)))
        (let ((tmp_5 (bvurem i #x00000200)))          ; nt: lane = i % 512
        (let ((tmp_6 (bvudiv i #x00000200)))          ;     pid  = i / 512
        (let ((tmp_7 (bvmul tmp_6 #x00000200)))
        (let ((tmp_8 (bvadd tmp_7 tmp_5)))            ;     idx = pid*512+lane
        (let ((tmp_9  (bvsrem tmp_8 #x00000008)))     ;     col = idx srem 8
        (let ((tmp_10 (bvsdiv tmp_8 #x00000008)))     ;     row = idx sdiv 8
        (let ((tmp_11 (bvmul tmp_10 #x00000008)))     ;     row * stride0(=8)
        (let ((tmp_12 (bvadd tmp_11 tmp_9)))          ;     off = row*8 + col
        (let ((tmp_13 (bvadd #x00000000 tmp_12)))
        (let ((tmp_14 (distinct tmp_13 i)))
        (let ((tmp_15 (or tmp_14 tmp_4)))
        tmp_15))))))))))))))))))
(check-sat)   ; → unsat
```

Z3 answers `unsat`: for the torch side `(i/32)*32 + i%32 = i` is the division
identity; for ninetoothed, `((i sdiv 8)*8 + i srem 8) = i` holds by the
*signed* division identity — with the concrete contiguous strides the 2-D
round-trip provably collapses to the linear index. Had the layout been
transposed or padded (`stride₀ ≠ size₁`), this scope would answer `sat` and
the driver would stop with `UNSUPPORTED` — refusing, not guessing. Before
specialization the strides are symbolic, offset ≠ `i` for some stride values,
and that is precisely why raw ninetoothed kernels are (correctly) rejected.

## 5. Operation-by-operation lowering

The encoder is one `TypeSwitch` with a rule per operation
(`TritonToSMTPass.cpp`). Anything not in the table is rejected with
`unsupported operation` — the pass fails; it never skips an op.

**Structure & indexing**

| TTIR | SMT encoding |
|---|---|
| `tt.get_program_id x` | `pid = i udiv BLOCK` (axis 0 only; y/z rejected) |
| `tt.make_range {s..e}` | `lane (+ s)`; also sets `BLOCK = e − s` |
| `tt.splat` | identity (scalar = per-lane value) |
| `arith.constant` (scalar/splat) | `Real` literal as exact dyadic rational / `BV` literal / `Bool` |

**Integer (bit-vector) ops** — `addi→bvadd`, `subi→bvadd∘bvneg` (no bvsub in
the dialect), `muli→bvmul`, `divsi/divui→bvsdiv/bvudiv`,
`remsi/remui→bvsrem/bvurem`, `shli/shrui/shrsi→bvshl/bvlshr/bvashr`,
`cmpi→bvcmp` with the exact predicate (`slt` ≠ `ult`), `eq/ne→(=)/(distinct)`.

**Bitwise ops dispatch on the operand sort** (this dispatch is what the
ninetoothed mask chains exercise):

| | on `iN` (bit-vectors) | on `i1` (booleans) |
|---|---|---|
| `arith.andi` | `bvand` | `and` |
| `arith.ori` | `bvor` | `or` |
| `arith.xori` | `bvxor` | `xor` |

**Float (ideal real) ops** — `addf→(+)`, `subf→(−)`, `mulf→(*)`,
`negf→(- x)`, `divf→(/)`, `math.fma→(+ (* a b) c)`,
`cmpf→(=)/(distinct)/(< ≤ > ≥)` (ordered and unordered predicates coincide:
reals have no NaN), `select→ite`, `max…f/min…f→ite(cmp)`,
`math.absf→ite(x < 0, −x, x)`.

One subtlety worth stating in a report: **SMT-LIB real division is a total
function that is unconstrained at zero denominators.** Both kernels see the
*same* division function, so proving equivalence remains sound; but `a/b` and
`a·(1/b)` are *not* judged equivalent (at `b = 0` the arbitrary function is
applied to different arguments). The unit test
`test_division_at_zero_is_uninterpreted` pins this behavior down.

**Bool↔storage casts** (the idioms frameworks use to store predicates):

| TTIR | SMT encoding |
|---|---|
| `arith.extui i1→iN` | `ite(b, 1, 0)` at width N |
| `arith.uitofp i1→float` | `ite(b, 1.0, 0.0)` |
| `tt.bitcast ptr→ptr` | identity on (array, offset); sorts reconciled at the load/store |
| store `iN` into an `i1` buffer | value `≠ 0` (byte-backed bool: 0 = false, nonzero = true) |
| store `i1` into an `iN` buffer | **rejected** (lowerings disagree on the written byte: NVIDIA sign-extends to `0xff`) |
| load at a different sort than the buffer | **rejected** (the ideal value cannot represent the raw byte) |

All *other* casts (`extsi`, `trunci`, `extf`, `truncf`, `sitofp`, value-level
bitcasts, …) remain rejected — widening a bool for storage is
semantics-preserving by construction; general width changes are future work.

**Memory**

| TTIR | SMT encoding |
|---|---|
| pointer argument | `(Array (BV 32) sort(pointee))`, offset 0 |
| `tt.addptr p, off` | same array, `offset + off` (offsets must be 32-bit) |
| `tt.load p, mask, other` | `ite(mask, (select arr off), other)`; without `other`: raw `select` |
| `tt.store p, v, mask` | recorded as the function's single store effect (exactly one required) |

Applied to the torch kernel of §2.1, the emitted terms are (scope 1, verbatim):

```smt2
(let ((tmp_0 (bvurem i #x00000020)))        ; %2  make_range  → lane
(let ((tmp_1 (bvudiv i #x00000020)))        ; %0  program_id  → pid
(let ((tmp_2 (bvmul tmp_1 #x00000020)))     ; %1  muli pid, 32
(let ((tmp_3 (bvadd tmp_2 tmp_0)))          ; %4  addi        → xindex (= i)
(let ((tmp_4 (bvadd #x00000000 tmp_3)))     ; %7/%10/%15 addptr offsets
(let ((tmp_5 (select arg1 tmp_4)))          ; %11 load b
(let ((tmp_6 (* tmp_5 (/ 3.0 4.0))))        ; %12 mulf b, 0.75   ← exact rational
(let ((tmp_7 (bvadd #x00000000 tmp_3)))     ; %7  addptr (a's offset)
(let ((tmp_8 (select arg0 tmp_7)))          ; %8  load a
(let ((tmp_9 (+ tmp_8 tmp_6)))              ; %13 addf
(let ((tmp_10 (bvslt tmp_3 #x00000020)))    ; %5  cmpi slt → xmask
```

and the ninetoothed function contributes the `sdiv/srem` addressing plus its
mask chain — ten `(and …)` conjuncts folded left, one per `andi` in the TTIR.

## 6. The equivalence query (scope 1)

For every output array the encoder builds each function's **final state at
index `i`**:

```
final(f) = ite(store_mask, stored_value, out[i])     -- out[i] = initial content
```

and asserts the *negation* of equivalence:

```smt2
(assert (distinct final(src) final(tgt)))
(check-sat)
```

- `unsat` — no assignment of the shared symbolic inputs (`arg0`, `arg1`,
  initial `arg2`, and `i`) makes the final states differ ⇒ **EQUIVALENT**.
  The masked case is covered automatically: where both masks are false, both
  sides keep `out[i]` and the `distinct` is false.
- `sat` — Z3's model *is* a concrete counterexample: input arrays, initial
  output content, and the failing index.

If the two functions store to *different* output arguments, both arrays are
compared (a function that doesn't write an array contributes its initial
state), so writing to the wrong destination is caught, not masked.

### 6.1 Verdicts for the demo pair

Three runs, three teachable outcomes:

**(a) Inductor kernel against itself → `EQUIVALENT`.** Baseline sanity: scope
0 `unsat`, scope 1 `unsat`.

**(b) ninetoothed vs Inductor, full 2³² index space → `NOT_EQUIVALENT`.**
Genuinely so — Z3's model returns the failing index `i = #x80000008`, an
index with the top bit set (a *negative* `xindex` under signed comparison).
Ninetoothed guards
every quantity with both `< bound` and `>= 0`; Inductor emits only
`xindex < 32`, because its launcher never creates such program ids. For an
index like `i = −1`: Inductor's mask is `true` (−1 < 32 signed) and it would
store, ninetoothed's mask is `false` and it would not. The checker treats a
kernel as a total function over every conceivable `(pid, lane)` — it has no
notion of the launch grid — and faithfully reports that the two functions
differ *as functions*. This is the modeling boundary, demonstrated by the
tool itself.

**(c) ninetoothed vs Inductor, restricted to the instance's extent →
`EQUIVALENT`.** The artifact instance has 32-element buffers; indices ≥ 32
don't exist in the real output. The demo appends one line to the equivalence
scope only —

```smt2
(assert (bvult i #x00000020))     ; i < numel
```

— at the SMT-LIB level (scope 0 stays fully universal), and Z3 proves
`unsat`: **for every index of the actual output, on every input, both
compilers compute the same function.** For all five specialized demo pairs:

```
add    all-indices=NOT_EQUIVALENT  i<numel=EQUIVALENT
mul    all-indices=NOT_EQUIVALENT  i<numel=EQUIVALENT
div    all-indices=NOT_EQUIVALENT  i<numel=EQUIVALENT
sub    all-indices=NOT_EQUIVALENT  i<numel=EQUIVALENT
relu   all-indices=NOT_EQUIVALENT  i<numel=EQUIVALENT
```

### 6.2 A real counterexample, decoded

Negative control: specialize the ninetoothed kernel with the *wrong* alpha
(0.5 instead of 0.75) and re-check against Inductor's 0.75 kernel. Z3, verbatim:

```
unsat                                   ← scope 0: addressing still identity
sat                                     ← scope 1: the outputs CAN differ
(
  (define-fun arg1 () (Array (_ BitVec 32) Real)
    ((as const (Array (_ BitVec 32) Real)) 4.0))       ; b ≡ 4.0
  (define-fun i () (_ BitVec 32) #x00000009)           ; failing index: 9
  (define-fun arg2 () (Array (_ BitVec 32) Real)
    ((as const (Array (_ BitVec 32) Real)) 5.0))       ; initial out ≡ 5.0
  (define-fun arg0 () (Array (_ BitVec 32) Real)
    ((as const (Array (_ BitVec 32) Real)) 0.0))       ; a ≡ 0.0
)
```

Read it back: at index 9 (< 32, a live element), ninetoothed-with-bug stores
`0 + 0.5·4 = 2.0` while Inductor stores `0 + 0.75·4 = 3.0`. The model is an
executable test case — you could allocate those arrays, run both kernels, and
watch element 9 disagree. *Proofs when the kernels agree, tests when they
don't.*

## 7. Soundness posture: what is proven, assumed, rejected

**Proven** (relative to the assumptions below): for straight-line,
single-store, identity-addressed kernel pairs, no input valuation
distinguishes the two functions' output — over *all* 2³² indices in the
standard query, or all valid indices in the extent-bounded demo variant.

**Assumed** (deliberate idealizations, stated up front):

- floats behave as mathematical reals — IEEE rounding/NaN/±inf effects are
  invisible by design;
- real division at a zero denominator is the same arbitrary value for both
  kernels (SMT-LIB semantics);
- distinct pointer arguments address disjoint, valid buffers (no aliasing, no
  out-of-bounds UB, no provenance);
- a single, race-free kernel launch; loads observe the entry memory state.

**Rejected loudly** — the checker's central discipline is that *everything
outside the validated contract fails the pass or returns `UNSUPPORTED`;
nothing falls through to a silent "equivalent"*:

- any unsupported operation (reductions, `tt.dot`, loops/`scf`, transcendental
  `math.*`, general casts, atomics, RNG, …) — pass error naming the op;
- more than one store, program-id axes y/z, non-32-bit offsets, non-finite
  float constants, signature mismatch — pass error;
- non-identity addressing (transposed/shifted/strided-symbolic stores) —
  scope 0 `sat` ⇒ `UNSUPPORTED`.

The sweep over the 41-operator artifact set exercises this posture end to
end: 17 Inductor kernels are proven self-equivalent (abs, add, bitwise_and/
not/or, clamp, div, eq, ge, gt, le, lt, mul, ne, neg, relu, sub), and all 24
others are rejected with a *specific* diagnostic (`unsupported operation
'tt.reduce'`, `only program_id axis 0 is supported`, scope-0 `sat`, …) —
never a wrong verdict.
